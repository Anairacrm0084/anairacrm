# Anaira Guest OTP — Production Setup

This build uses a dedicated guest verification bridge for hotel booking.

## Email OTP
Set these server-side environment variables:

- `RESEND_API_KEY`
- `RESEND_FROM`

The guest's entered email receives the OTP. Anaira/hotel notification email is not used as the OTP recipient.

## Phone OTP
Set these server-side environment variables:

- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_FROM`

The guest's entered mobile number receives the OTP.

## Required security key
Set:

- `ANAIRA_SECRET_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

`ANAIRA_SECRET_KEY` hashes OTP values and contact challenges. The service role is used only by the server-side OTP bridge.

## Database
Apply:

`supabase/migrations/20260927_phase90_guest_otp_bridge.sql`

The migration creates `anaira_guest_otp_challenges`, locks direct table access, adds a verification RPC, and changes the hotel booking transaction so the public customer path requires a verified challenge.

## Customer flow

Guest email/phone → Send OTP → provider delivers OTP → Verify OTP → verification challenge marked verified → booking RPC validates the exact guest contact → reservation transaction starts.

## Provider credentials are intentionally not embedded
The ZIP contains the complete integration code, but provider API credentials must be supplied in the production deployment's server environment. No real Resend/Twilio secret can be generated by the application itself.
